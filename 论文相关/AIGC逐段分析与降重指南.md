# AIGC 检测逐段分析与降重指南

> 检测报告：Paperyy AIGC检测，2026-05-16
> 总体疑似率：15.9%（高度疑似占比 15.1%）
> 高AIGC段落数：49段

---

## 总体诊断

检测器判定"高度疑似AI生成"的段落集中暴露以下几类问题：

| 问题类型 | 出现频率 | 典型表现 |
|---|---|---|
| 教科书式总结 | 极高 | "A做了X，B做了Y，但均未……本文为此……" |
| 安全型hedging | 高 | "不能简单宣称""仍需进一步""更适合定位为" |
| 并列排比句式 | 高 | "低正则增强……二层传递提供……本地训练提高……" |
| 机械因果链 | 中 | "由于X→导致Y→从而Z→因此采用W" |
| 过度完整 | 中 | 每段都有"现象+原因+限制+结论"全套 |
| 英文学术八股 | 高 | "offers an alternative paradigm""remains challenging due to" |

**核心判断逻辑：** 检测器抓的不是"写得好不好"，而是"是不是太均匀、太安全、太工整"。真人写论文会有信息密度不均匀、偶尔跳跃、某些地方偷懒只写半句的特征。AI输出则每段都很"完整"。

### 段落 1 | AIGC概���: 96.9% | 位置：中文摘要

**原文：**
> 实验在 MovieLens-100k 和 MovieLens-1m 上展开，重点比较了注意力结构、图融合策略、正则化和消息传递层数等参数的影响。在 MovieLens-100k 上，最终联邦配置的 HR@10 达到 0.7752、NDCG@10 达到 0.4828，超过了中心化 NCF 基线和无图均值聚合基线。不过在 MovieLens-1m 上，联邦模型还没达到中心化基线的水平，邻居筛选策略和训练参数在数据量变大后需要重新调整。整体来看，双图可信邻居筛选配合个性化本地训练确实能提升联邦推荐的效果，但适用范围仍受数据规模限制。

**为什么判定为AI生成：**
1. **完美的"好消息→坏消息→平衡结论"三段式**：先说100k好，再说1m差，最后给一个"确实有效但有限制"的圆滑总结。这是AI回答问题时的标准安全模板。
2. **hedging收尾**："但适用范围仍受数据���模限制"——真人写摘要不会在最后主动泼自己冷水，这是AI的"安全训练"产物。
3. **"整体来看"这个连接词**：AI特别喜欢用"整体来看""总体而言"来引出最终结论。
4. **信息排列过于对称**：100k的结果有多详细，1m就有多详细，构成完美对比。

**怎么改（让它像本科生写的）：**
> 实验用 MovieLens-100k 和 MovieLens-1m 两个数据集。在 100k 上最终跑到 HR@10=0.7752、NDCG@10=0.4828，比中心化 NCF 和无图聚合的结果都高。1m 上还没追上中心化基线，邻居筛选的参数需要针对大数据量重新调。

**改动要点：** 删掉开头的"重点比较了XXX等参数的影响"（太概括），删掉尾巴的哲学总结，只保留事实陈述。

### 段落 2 | AIGC概率: 96.9% | 位置：英文摘要第一段

**原文：**
> Recommender systems continuously record user behavior such as ratings, clicks, and browsing history, and leverage these chronologically ordered records to model evolving user interests. Traditional centralized approaches collect all interaction data on a central server for model training, which raises privacy concerns in data storage and access control. Federated learning offers an alternative paradigm that retains raw data on local devices, yet achieving competitive recommendation accuracy under this distributed setting remains challenging due to user-level data sparsity and heterogeneous preferences.

**为什么判定为AI生成：**
1. **经典的"背景→问题→方案→挑战"四步开场白**：这是GPT/Claude写学术introduction的标准模板。
2. **"offers an alternative paradigm"**："paradigm"一词是AI学术写作的高频标志词。
3. **"remains challenging due to"**：AI最爱的"困难在于"句式。
4. **过于流畅的因果链**：每句话都完美承接上一句，没有任何信息跳跃。真人写英文摘要往往会更直接地进入主题。
5. **枚举过于完整**："ratings, clicks, and browsing history"——三个并列的例子，AI特别喜欢给三个。

**怎么改：**
> Federated recommendation systems train models without centralizing user interaction data, addressing privacy requirements in modern platforms. However, each client holds only sparse local records, making it difficult to learn high-quality representations from local data alone. This thesis builds a federated system on top of NCF and introduces dual-graph trusted-neighbor selection on the server to improve aggregation quality.

**改动要点：** 不要从"推荐系统是什么"讲起（评审老师知道），直接说联邦推荐的核心矛盾。去掉"paradigm""leverage""evolving"等AI高频词。第一句就点明主题而不是铺垫三句再入题。

### 段落 3 | AIGC概率: 95.3% | 位置：英文摘要第二段

**原文：**
> This thesis implements a federated personalized recommendation system built upon Neural Collaborative Filtering (NCF). On the client side, each user retains private embeddings and prediction-layer parameters locally; a multi-head attention module with learnable positional encoding operates on the local interaction history to capture short-term interest, which is concatenated with the long-term user embedding and candidate item embedding before being fed into a multilayer perceptron for interaction prediction. On the server side, the system constructs a behavior correlation graph from uploaded item embeddings and an interest semantic graph from uploaded interest encodings, then selects their intersection as the trusted neighbor set...

**为什么判定为AI生成：**
1. **"On the client side... On the server side..."** 对称结构：AI极其喜欢用这种平行结构来组织信息。
2. **一句话塞进了整个系统架构**：中间那个从"a multi-head attention module"到"interaction prediction"的超长定语从句，是AI把所有信息压缩进一个语法完整句子的典型做法。真人会分成几个短句。
3. **术语堆砌密度过高**：每个名词前面都有一堆修饰词（"learnable positional encoding""local interaction history""short-term interest"），读起来像是把所有关键词都塞进去了。
4. **"which is concatenated with... before being fed into"**：被动语态的多级嵌套，标准AI句式。

**怎么改：**
> This thesis implements a federated recommendation system based on NCF. Clients keep their own embeddings and train a local prediction model with a multi-head attention layer that encodes recent interaction sequences. The server collects uploaded item embeddings and interest encodings, builds two similarity graphs from them, and takes the intersection of neighbors from both graphs as the trusted set for aggregation. Laplace noise is added to item embeddings before upload; cumulative privacy budgets are tracked under three composition methods.

**改动要点：** 拆成短句，去掉嵌套从句，一句一个事实。不用"On the X side"对称结构。

**为什么判定为AI生成：**

2. **"encompass multiple batches of controlled comparisons covering..."**：过度正式，后面跟一长串并列项。

### 段落 5 | AIGC概率: 82.6% | 位置：第一章绪论

**原文：**
> 但光是不上传原始数据还不够。研究发现，上传的梯度和物品嵌入照样可能被攻击者反推出用户行为[4,5]，梯度扰动类攻击还能破坏训练过程[6]。所以联邦推荐不能只做到"数据留本地"就完事了，传参数的时候也得加保护措施。已有差分隐私推荐研究通常采用 Laplace 噪声等机制对上传参数进行保护，并观察不同隐私参数对推荐效果的影响[7]。但如果缺少明确的敏感度裁剪和噪声校准，仅凭加噪和朴素组合预算仍难以支撑严格的差分隐私声明。

**为什么判定为AI生成：**
1. **前半段口语+后半段突然学术化**：前面"就完事了""传参数的时候也得加保护"很口语，后面突然变成"已有差分隐私推荐研究通常采用……并观察……"——这种风格断裂是"让AI先写正式版再让AI改口语化"的痕迹。
2. **最后一句是典型hedging**："但如果缺少……仅凭……仍难以支撑……"——AI的标准"限制性结论"格���。
3. **完美的"提出问题→引文献→指出不足"链条**：这个三步走太流畅了。

**怎么改：**
> 不过只是把数据留本地还不够安全。文献[4,5]表明攻击者能从上传的���度和嵌入反推用户行为，[6]则展示了梯度扰动攻击如何破坏训练。刘刚等人[7]试过给上传参数加Laplace噪声，但他们没有做敏感度裁剪，隐私保证比较粗糙。

**改动要点：** 去掉口语/学术的风格断裂，保持一个统一的语气。最后不要用"仍难以支撑严格的差分隐私声明"这种AI式总结，直接说"隐私保证比较粗糙"更像人话。

### 段落 6 | AIGC概率: 51.1% | 位置：第一章研究内容

**原文：**
> 在理论方面，本文提出了一种在服务端挑选可靠邻居的新方法。在联邦推荐的服务端聚合过程中，如果只看单一表征来计算用户之间的相似度，邻居判断容易受到局部特征、训练噪声和稀疏交互的影响。有些用户可能只在某一个标准下看起来相似，但实际上并不是一类人。如果把这些人当成邻居，就会给系统混进没用的干扰信息，导致推荐变差。为了解决这个问题，本文同时建了两张图。

**为什么判定为AI生成（虽然概率不算太高）：**
1. **"为了解决这个问题，本文……"**：这是AI写论文的万能过渡句，出现一次不算什么，但如果全文到处都是就会被检测器抓住。
2. **问题描述过于铺垫**：用了三句话描述问题才引出方案，显得刻意。
3. **并列三件事**："局部特征、训练噪声和稀疏交互"——AI喜欢列三个。

**怎么改：**
> 服务端邻居筛选方面，只用一种相似度来选邻居不太稳，有些用户可能物品嵌入接近但兴趣方向完全不同。本文同时建了两张图——一张看行为关联，一张看兴趣语义——取交集来过滤掉只在单一维度上相似的用户。

**改动要点：** 去掉"为了解决这个问题"的万能句式，直接说怎么做。把问题和方案压缩到一起而不是分成"问题描述→方案引出"两段。

### 段落 7 | AIGC概率: 86.8% | 位置：第一章研究内容

**原文：**
> 在方法方面，本文把多头注意力机制用在了客户端的兴趣分析上。注意力机制在传统集中收集数据的系统里确实挺好用。但是在联邦学习这种数据全部分开的情况下，特别是每个用户手里只有几十条操作记录的时候，它还能不能稳定发挥作用，其实并不确定。为了搞清楚这个问题，本文做了很多组对比实验。系统对比了单头和多头注意力，测试了不同长度的历史记录，还试了加不加位置编码。

**为什么判定为AI生成：**
1. **标准的"肯定→转折→不确定→本文验证"四步走**：先说好用→但不确定→为了搞清楚→本文做了实验。这个逻辑链太教科书了。
2. **刻意口语化的节奏过于均匀**：每句话都差不多长，语气都差不多"随意"，反而不自然。真人的口语化是偶尔的、不均匀的。
3. **末尾的三并列**："对比了单头和多头注意力，测试了不同长度的历史记录，还试了加不加位置编码"——三个并列动宾结构。

**怎么改：**
> 客户端用多头注意力来提取用户的短期兴趣。注意力机制在集中式推荐里效果好，但联邦场景下每个用户只有几十条记录，所以本文专门测了单头、多头、不同历史长度和有无位置编码的组合，看在数据极少的情况下注意力还能不能帮上忙。

**改动要点：** 合并成更紧凑的两句话，不要搞"提出问题→引出验证"的两步走。

### 段落 8 | AIGC概率: 94.3% | 位置：第一章文献综述

**原文：**
> 联邦推荐最初要解决的是"能不能跑通"的问题。Zhang等[3]先试了用部分数据预训练全局模型再下发，证明全局信息对本地推荐确实有帮助。刘刚等人[7]在上传参数的时候加了Laplace噪声，算是第一次在联邦推荐里考虑隐私保护。但这些早期工作用的聚合方式都比较粗糙，没怎么管不同用户之间的差异。Zhang等人[8]后来针对地理兴趣点场景做了PrefFedPOI，在客户端加了偏好感知模块来处理数据稀疏的问题，算是开始关注个性化了。

**为什么判定为AI生成：**
1. **完美的时间线叙事**："最初→先→第一次→但→后来→算是开始"——这是让AI写"XXX领域的发展历程"时的标准输出格式。
2. **每篇文献都是同一个句式**："XX等人做了YY，证明/说明了ZZ"。
3. **结尾的"评价"都很像**："算是第一次考虑""算是开始关注"——AI特别喜欢给文献加上"意义定位"。
4. **"但这些早期工作用的聚合方式都比较粗糙"**：这句做承转太顺滑了，像是AI在写transition。

**怎么改：**
> 早期联邦推荐工作主要验证可行性。Zhang等[3]用预训练全局模型辅助本地推荐；刘刚等人[7]给上传参数加了Laplace噪声。这些方法的聚合都是简单平均，不考虑用户差异。后续Zhang等人[8]的PrefFedPOI开始在客户端做偏好感知来应对数据稀疏。

**改动要点：** 去掉"算是第一次""算是开始关注"这种评价性语言。文献综述应该像议论文——"他们做了X，但有Y问题"，而不是像讲故事一样排时间线。

### 段落 9 | AIGC概率: 61.3% | 位置：第一章文献综述

**原文：**
> 做联邦推荐的表示学习，说白了就两个难点：一是本地数据太少怎么学好表示，二是上传参数的时候怎么防泄露。表示质量方面，马文骏等人[17]用自监督对比学习来提升多模态表示；王熙菲和巫朝霞[18]在联邦框架下用VAE加聚类来增强本地的生成能力。隐私方面，Lu等人[19]引入了区块链做去中心化聚合；Xu等人[20]在联邦推荐里加了差分隐私，用MovieLens数据集测了精度和隐私的权衡。

2. **"表示质量方面""隐私方面"**：用"XX方面"做分类引导语也是AI高频用法。

**改动要点：** 不要每篇文献单独一句话并列排开。把几篇文献串成一个论点：它们试了什么、共同的问题是什么。

### 段落 10 | AIGC概率: 82% | 位置：第一章文献综述

**原文：**
> 除了怎么共享参数，联邦推荐还得应对数据合规的要求。Yuan等人[27]做了联邦反学习，让用户退出时可以把之前的贡献清掉。他们后来还专门分析了交互级的成员推断攻击有多大威胁[4]。这些研究都在说明一个问题：光靠联邦学习的框架本身是不够安全的，必须再加上差分隐私之类的手段，而且要把每一轮的隐私消耗都记清楚。

**为什么判定为AI生成：**
1. **"这些研究都在说明一个问题：……"**：AI的经典"总结升华"句式。把几篇文献概括成"一个问题"，然后引出自己的观点。

**怎么改：**

**改动要点：** "这些研究都在说明一个问题"改成简单的"这说明"。删掉"除了怎么共享参数"这个过渡引入。

### 段落 11 | AIGC概率: 94.8% | 位置：第一章问题分析

**原文：**

## 总结：降AIGC的核心策略

### 你的论文被判高AIGC的根本原因

1. **同一个结论说太多遍**：低正则+二层传播+2轮训练这个结论在第五章出现了至少5次（段落37/38/39/40/43/46），每次换个说法重述。检测器对这种"重复表述同一事实"非常敏感。

2. **过度hedging**：到处都是"不能简单宣称""仍需进一步""更适合定位为"。这是AI安全训练的直接产物。

3. **结构太对称**：几乎所有段落都有"先说数据→再解释原因→最后给限制"的三步走。

4. **解释性冗余**：每个表格后面都有一段"换种方式再说一遍表格内容"的文字。

5. **英文摘要整段是AI标准输出**：用了太多AI高频词（paradigm, leverage, remains challenging, yields）。

### 最有效的五个降重动作（按优先级）

| 优先级 | 动作 | 预计降低幅度 |
|---|---|---|
| 1 | 删掉重复表述：同一个结论只说一次 | -3~4% |
| 2 | 英文摘要完全重写（目前占了4段高AIGC） | -2~3% |
| 3 | 删掉所有hedging句（"不能简单宣称""仍需限定在"） | -2% |
| 4 | 致谢用真实细节重写 | -1% |
| 5 | 实验分析段的"原因解释"压缩到一句话 | -2~3% |

### 注意事项

- **不要用AI来改AI**：不要让ChatGPT/Claude帮你"降AIGC"——它们改出来的文字照样会被检测出来，因为文字风格没有本质变化。
- **最有效的方法是删除**：把重复的段落直接删掉，比"换种方式重写"有效得多。
- **加入只有你自己知道的细节**：调试过程中的具体错误、你是怎么发现bug的、和同学讨论的具体场景——这些AI生成不出来。
- **允许不完美**：不需要每段都有"原因解释"，不需要每个实验都讨论"局限性"。有些地方就是列个数据，不解释，反而更像人写的。
